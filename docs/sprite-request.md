# 방향별 스프라이트 요청 — 「이번 웨이브는 못 막습니다」

## 왜 필요한가

지금 게임은 적이 어느 쪽으로 걸어가든 **정면만 보고**, 포탑이 어디를 쏘든 **한 방향만 본다.**
그림이 종류당 한 장씩(정면)뿐이라서다.

포탑의 조준 각도는 **이미 계산되고 있다**(`index.html:2777` `t.angle = Math.atan2(dir.dy, dir.dx)`).
그릴 그림이 없어서 안 쓰고 있을 뿐이다. **그림만 오면 코드는 바로 붙는다.**

## 무엇을 그리나 — 44장

기존 15장은 그대로 쓴다. 아래는 **추가로 필요한 것**이다.

### 포탑 7종 x 4방향 = 28장

기존 그림이 **NW(왼쪽 위)** 를 보고 있다. 그것을 `nw` 로 삼고 나머지를 채운다.

```
종류   shredder · frost · eroder · mortar · marksman · arc · mint
방향   n(위) · ne(오른쪽 위) · e(오른쪽) · se(오른쪽 아래)
```

**나머지 넷은 그리지 않는다** — 좌우 뒤집기로 만든다:

```
nw ← ne 뒤집기        기존 그림이 이 자리다
w  ← e  뒤집기
sw ← se 뒤집기
s     ← 이건 대칭이 없다. 아래 「s 를 어떻게 할까」 참고
```

즉 실제로는 `n · ne · e · se` 넷만 새로 그리면 8방향이 선다.
`s`(아래)는 아이소메트릭에서 포신이 화면 앞으로 오는 각도라 짧게 보인다 —
**한 장 더 그려 주면 좋고, 어려우면 `se` 로 대신한다.** 그리기 쉬운 쪽으로 정해 달라.

### 적 8종 x 2방향 = 16장

기존 그림이 **정면(아래를 향해 걸어오는 모습)** 이다. 그것을 `down` 으로 삼는다.

```
종류   grunt · swarm · swift · armored · elite · immune · regen · warded
방향   up(등을 보임) · side(옆모습)
```

`left`/`right` 는 `side` 를 뒤집어 만든다. 그래서 **2장이면 4방향이 선다.**

## 규격 — 기존 그림과 같게

```
크기       256 x 256 (기존 그림과 동일)
배경       투명 (알파 채널)
형식       PNG
스타일     기존 그림과 같은 픽셀아트. 같은 팔레트·같은 외곽선 굵기
```

**같은 종류의 방향 넷은 같은 캐릭터여야 한다.** 색·비율·장식이 방향마다 달라지면
회전이 아니라 다른 타워가 된다.

## 파일 이름

```
assets/sprites/towers/marksman.png        기존 — 이것이 nw 다
assets/sprites/towers/marksman-n.png      새로
assets/sprites/towers/marksman-ne.png
assets/sprites/towers/marksman-e.png
assets/sprites/towers/marksman-se.png

assets/sprites/enemies/grunt.png          기존 — 이것이 down 이다
assets/sprites/enemies/grunt-up.png       새로
assets/sprites/enemies/grunt-side.png
```

낱장이 편하면 위대로, 아틀라스가 편하면 아래 「아틀라스로 줄 때」를 따른다.
**둘 중 아무 쪽이나 좋다** — 코드에서 양쪽 다 받는다.

## 방향의 기준 — 화면 좌표다

```
n   화면 위쪽        y 가 줄어드는 쪽
e   화면 오른쪽      x 가 느는 쪽
s   화면 아래쪽      y 가 느는 쪽
w   화면 왼쪽        x 가 주는 쪽
```

적은 **위에서 아래로** 내려오는 것이 기본이라 `down` 이 가장 많이 보인다.
포탑은 적이 어디 있느냐에 따라 여덟 방향을 다 쓴다.

## 아틀라스로 줄 때

형제 프로젝트(after-work-exorcist)와 같은 형식을 쓴다. 그쪽 코드를 그대로 옮겨 올 수 있다.

```json
{
  "characterId": "marksman",
  "game_input": "atlas.png",
  "cell": { "width": 256, "height": 256 },
  "frame_layout": {
    "rows": {
      "n":  [{ "x": 0, "y": 0, "w": 256, "h": 256 }],
      "ne": [{ "x": 0, "y": 256, "w": 256, "h": 256 }],
      "e":  [{ "x": 0, "y": 512, "w": 256, "h": 256 }],
      "se": [{ "x": 0, "y": 768, "w": 256, "h": 256 }]
    }
  },
  "animation": {
    "rows": {
      "n":  { "frames": 1, "loop": true },
      "ne": { "frames": 1, "loop": true },
      "e":  { "frames": 1, "loop": true },
      "se": { "frames": 1, "loop": true }
    }
  }
}
```

## 걷기 애니메이션은 다음 단계다

지금은 **방향당 한 장**이면 된다. 적이 걷는 동작(2~4프레임)은 방향이 붙고 난 뒤에
따로 받는다. 한 번에 다 하면 그림이 네 배가 되고, 방향만으로도 화면이 크게 달라진다.

애니메이션까지 갈 때는 위 아틀라스 형식의 `frames` 를 늘리고 행 이름을
`side_walk` 처럼 `{방향}_{동작}` 으로 바꾼다. 형제 프로젝트가 그렇게 하고 있다.

## 우선순위 — 나눠서 줘도 된다

```
1순위   적 8종 x side          8장    가장 눈에 띈다. 적은 가로로도 걷는다
2순위   포탑 7종 x ne · e      14장   포탑이 오른쪽을 보게 된다
3순위   적 8종 x up            8장    위로 가는 구간이 있는 판에서 필요
4순위   포탑 7종 x n · se      14장   나머지
```

**1순위만 와도 붙일 수 있다.** 없는 방향은 기존 그림으로 대신하므로 중간에 깨지지 않는다.

## 참고 — 지금 그림

```
포탑   아이소메트릭(비스듬히 내려다본 시점). 받침 + 포신 구조
적     정면 뷰. 서 있는 모습
```

둘이 시점이 다른데 그대로 유지해 달라. 게임 화면에서 이미 그렇게 보이고 있고,
바꾸면 15장을 전부 다시 그려야 한다.
